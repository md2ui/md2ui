# tests-render: design exercises

Each folder here is an **exercise**: a real-world screen re-authored as md2ui Markdown, to try
what md2ui can draw and find where it stops. The design references were **picked at random**
(app stores, Dribbble shots, Figma community files, public websites), not chosen to suit
md2ui, so an exercise shows both a capability and, where the render falls short, a limit.

Most were written without reading md2ui's pipeline: the authoring notes (`skills/`,
`THEME_GUIDE.md`) and the reference were the only inputs, so a gap between the render and the
reference is evidence about md2ui, not about one author's knowledge of the code.

## What a folder holds

| File | What |
|---|---|
| `content.md` | the exercise itself. **Its opening HTML comment names the source**: the reference URL, or `LLM generated` / `Unknown` where there is none |
| `THEME.md` | the theme written for it; it renders with this theme |
| reference image | where kept: the screenshot the exercise was written against |

Render one with `uv run md2ui render <folder>/content.md` (the `THEME.md` beside it is picked
up). Every `content.md` here is part of the render snapshot (`scripts/render_snapshot.py`), so a
change to md2ui that moves any of these pixels shows up there.

The names, places and figures in the content are the references' sample data or invented; the
exercise is the **shape**. Where a reference is a real product, its brands are only what the
screen showed.
